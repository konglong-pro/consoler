# Superseded Planning Docs

Replaced rules or plans live here when they must not be read as current instructions.

Superseded is narrower than completed or frozen:

- `completed`: implementation work is done; read closeout/status first.
- `frozen`: released baseline; can be referenced but not casually changed.
- `superseded`: replaced by a newer canonical rule, location, contract, ADR, or status entry.

Each superseded document must declare front matter with `status: superseded`, `read_by_default: false`, and `superseded_by`. Do not use superseded docs as current instructions unless an active doc explicitly points to them for historical context.
